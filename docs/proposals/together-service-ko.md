# 함께 하기 — 초대 · 비교 · 보내기 (기획안)

> 상태: 1단계는 PR #72로 구현됨. 2·3단계는 제안.
> 대상: `site/` (lovemedialogue.com).
> 마일스톤: 이 문서의 1·2단계는 **M1**, 3단계는 **M2**입니다 — `docs/MILESTONES.md`.

## 1. 무엇을 만드는가

한 사람이 100개의 질문에 답한 다음, **상대를 부르고, 두 사람의 답을 나란히 보고, 그 결과를
남기거나 보내는** 흐름을 사이트 안에서 끝냅니다.

지금 있는 것과 없는 것:

| 조각 | 상태 |
|---|---|
| 100문항 답하기, 브라우저에 저장 | 있음 |
| 답 링크 만들기 · 상대 답과 비교 · 답한 질문에서만 상대 답 공개 | 있음 (#67) |
| 초대 버튼 (질문집 링크, 답 없음) | 있음 (#72) — 옛 "둘이 함께 해보기"는 아무 데도 가지 않았습니다 |
| 결과를 메일로 (`mailto:`, 전송 없음) | 있음 (#72) |
| 공유 (`navigator.share` · 클립보드) | 있음 (#72) |
| 이미지로 저장 · 카카오 SDK | 없음 — 아래 2단계 |

## 2. 먼저 정해야 하는 것 — 링크는 한 종류가 아닙니다

이 기획의 모든 판단이 여기서 갈립니다. **링크마다 담긴 것이 다르고, 보낼 수 있는 곳도 다릅니다.**

| 링크 | 담긴 것 | 보내도 되는 곳 |
|---|---|---|
| **초대 링크** | 없음. 질문집 주소뿐 | 어디든 — SNS 피드, 오픈채팅, 단톡방 |
| **내 답 링크** | 내가 고른 100개의 답 | **상대 한 사람에게만** |
| **비교 링크** | 두 사람의 답 | **두 사람 사이에서만** |

지금 결과지의 "내 답 링크 만들기"가 만드는 것은 두 번째입니다. 이것을 SNS 피드에 올리면
**자기 답 100개를 공개하는 것**입니다. 그러니 SNS 공유 버튼이 붙어야 할 것은 첫 번째이고,
두 번째·세 번째에는 공유 버튼 대신 **경고**가 붙어야 합니다.

메모(왜 골랐는지, 상대가 뭘 고를지, 우리의 임시 원칙)는 **어느 링크에도 담기지 않습니다.**
지금도 그렇고, 앞으로도 그렇습니다.

## 3. 흐름 — 메시지 두 통으로 끝납니다

```
A: 답한다 → 결과지 → [상대에게 보내기]
      └─ 내 답 링크(A)  ──카톡/메일──▶  B

B: 링크를 연다 → "먼저 답해 주세요" (A의 답은 아직 안 보임)
   → 답한다 → 비교 화면(A vs B) → [비교 결과 보내기]
      └─ 비교 링크(A+B)  ──카톡/메일──▶  A

A: 링크를 연다 → 같은 비교 화면. 끝.
```

초대와 "내 답 보내기"는 **같은 버튼**입니다. B는 링크를 여는 순간 초대받은 것이고, 답을 채우면
그 자리에서 비교가 열립니다. 별도의 초대 화면도, 수락 버튼도 필요 없습니다.

아직 답하지 않은 사람에게 먼저 권하고 싶을 때만 **초대 링크**(답 없음)를 씁니다. 그 버튼이
지금 죽어 있는 "둘이 함께 해보기"의 자리입니다.

## 4. 화면과 문구

### 4.1 질문 페이지 아래 — 초대

지금: `둘이 함께 해보기` → `/` (아무 일도 일어나지 않음)
바꿈: **초대 버튼**. 답이 없어도 눌립니다.

```
이 질문, 혼자 답하고 끝내지 마세요.
같은 질문에 상대도 답하면 서로의 답을 나란히 볼 수 있어요.
[ 상대 초대하기 ]      ← 공유 시트 / 링크 복사
```

- 누르면 `navigator.share({ title, text, url })` — 폰에서는 카톡·메시지가 뜨는 기본 공유창.
- 공유 API가 없으면(데스크톱 대부분) 클립보드 복사 + 주소 노출.
- 링크: `https://lovemedialogue.com/marriage/` — **답이 담기지 않습니다.**

### 4.2 결과지 — 내 답 보내기

지금 있는 `내 답 링크 만들기`를 **`상대에게 보내기`**로 바꾸고, 경고를 버튼 옆으로 올립니다.

```
상대에게 보내기
이 링크에는 내가 고른 답 100개가 들어 있어요. 상대에게만 보내 주세요.
옆에 적은 메모는 담기지 않습니다.
[ 상대에게 보내기 ]    [ 링크 복사 ]
```

- 공유 시트는 띄우되, **SNS 피드에 올리는 것을 권하는 문구는 쓰지 않습니다.**
- 답이 하나도 없으면 버튼 대신 "먼저 질문에 답해야 보낼 답이 생겨요."

### 4.3 비교 화면 — 결과 보내기 · 메일

비교가 열린 뒤에만 나타납니다.

```
우리 비교 결과
[ 상대에게 보내기 ]   ← 비교 링크(두 사람 답). 1:1 전용
[ 메일로 보내기 ]     ← 아래 5장
[ 이미지로 저장 ]     ← 2단계
```

## 5. 메일로 보내기 — 서버 없이

사이트는 서버가 없습니다. 메일을 **보내 주는** 것은 불가능하고, 메일 앱을 **열어 주는** 것은
가능합니다. `mailto:`가 그것입니다.

```
mailto:?subject=결혼 100제 · 우리가 다르게 고른 질문
      &body=<요약 + 링크>
```

- 서버로 아무것도 가지 않습니다. 주소도, 답도. 사이트는 여전히 아무 요청을 하지 않습니다.
- 받는 사람은 비워 둡니다 — 메일 앱에서 직접 고르게. 우리가 주소를 아는 일이 없습니다.

**본문에 무엇을 담는가.** URL 길이 한계(안전하게 1,800자)가 100개 질문을 다 담기에는 부족합니다.
그러니:

```
우리가 다르게 고른 질문 23개 중 앞의 열 개

02. 서로 먹고 싶은 것이 다른 저녁, 어떤 원칙이 가장 편안할까요?
    나   · 둘 다 괜찮은 세 번째 메뉴를 새로 찾는다
    상대 · 각자 원하는 음식을 따로 먹는다
…

전체는 이 링크에서 볼 수 있어요:
https://lovemedialogue.com/marriage/result/#c=…
```

- 앞의 10개 + 전체 링크. 10개가 1,800자를 넘으면 넘지 않을 때까지 줄입니다.
- 링크에는 두 사람의 답이 들어 있으므로 본문 첫 줄에 **"이 메일에는 두 사람의 답이 들어 있어요."**

**메일 앱이 없는 기기**(데스크톱 웹메일만 쓰는 경우)에서는 `mailto:`가 아무 일도 하지 않습니다.
그래서 메일 버튼 옆에 항상 **[본문 복사]**를 같이 둡니다. 복사해서 붙여 넣으면 끝입니다.

## 6. SNS로 보내기

| 방법 | 무엇이 필요한가 | 판단 |
|---|---|---|
| **Web Share API** (`navigator.share`) | 없음 | **채택.** 폰의 기본 공유창이 뜨고 카톡·메시지·메일이 그 안에 있습니다. 제3자 스크립트 0개 |
| 클립보드 복사 | 없음 | **채택.** 공유 API가 없는 데스크톱의 기본 동작 |
| 카카오톡 공유 (JS SDK) | 카카오 앱 키, 도메인 등록, 외부 스크립트 | **2단계 검토.** 예쁜 카드가 뜨지만 카카오 스크립트를 사이트에 싣게 됩니다 — 지금 사이트는 제3자 스크립트가 하나도 없고, 그걸 깨면 개인정보 처리방침에 고지 대상이 생깁니다 |
| X/페이스북 공유 URL | 없음 | **보류.** 공개 피드에 올리는 경로라 답 링크와 상성이 나쁩니다 |

**공개 피드에 올릴 수 있는 것은 초대 링크뿐입니다.** 답 링크·비교 링크에는 공유 시트를 띄우되
"상대에게만"이라고 말하고, 피드형 서비스로 직행하는 버튼은 만들지 않습니다.

## 7. 단계

### 1단계 — 사이트 안에서 끝내기 (서버 없음, 의존성 없음)

1. `둘이 함께 해보기` → **초대 버튼**으로 교체, `navigator.share` + 복사 폴백
2. 결과지 `내 답 링크 만들기` → **`상대에게 보내기`**, 경고 문구를 버튼 옆으로
3. 비교 화면에 **비교 링크 만들기** (두 사람 답을 한 링크에)
4. 비교 화면에 **메일로 보내기**(`mailto:`) + **본문 복사**
5. 링크 종류별 경고 문구

새로 필요한 것 없음. 테스트는 링크 3종의 내용물, 길이 한계, 경고 문구 노출.

### 2단계 — 남기기

6. **이미지로 저장** — 캔버스로 카드 한 장. 단, **답은 넣지 않습니다**: "우리가 다르게 고른
   질문 23개"처럼 세는 것까지. 그래야 피드에 올려도 안전합니다
7. 카카오톡 공유 SDK (앱 키 필요 · 처리방침 고지 필요)

### 3단계 — 계정이 필요해지면 (= M2)

8. 100제를 앱/서버의 초대·워크스페이스 흐름에 올리기
9. 서버에서 메일 발송(Resend) — **답이 서버로 갑니다.** 처리방침·동의·보관기간이 전부 따라붙습니다.
   1·2단계로 충분한지 먼저 확인하고 결정할 일입니다

## 8. 지키는 선

- 점수·판정·궁합 없음. 세는 것은 "두 사람 모두 답한 질문 수"와 "다르게 고른 질문 수"까지
- 답은 브라우저 밖으로 나가지 않음. 나가는 순간은 **사용자가 링크를 직접 보낼 때뿐**
- 메모는 어떤 링크에도 담기지 않음
- 상대의 답은 내가 같은 질문에 답한 뒤에만 열림 (지금 규칙 유지)
- 제3자 스크립트 0개 유지 (2단계 카카오는 예외로 결정할 때만)

## 9. 열린 결정

1. **비교 링크의 길이.** 두 사람 답이면 200자가 조금 넘습니다. 카톡·메일 모두 문제없지만,
   나중에 200제가 나오면 압축이 필요합니다. 지금 만들어 둘지, 그때 할지
2. **카카오톡 공유**를 2단계에서 실제로 넣을지 (제3자 스크립트를 들일지)
3. **이미지 카드**에 무엇까지 넣을지 — 질문 수만인지, 파트 이름까지인지
4. 3단계로 갈지 — 즉 계정·서버·메일 발송까지 갈지
